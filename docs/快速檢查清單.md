## ?? 連接測試 (可選)

在 PowerShell 中運行：

```powershell
$connStr = "Data Source=192.168.1.111;Initial Catalog=Pi news;User ID=sa;Password=!QAZxsw2;Connection Timeout=30;TrustServerCertificate=true;Encrypt=true"

$conn = New-Object System.Data.SqlClient.SqlConnection
$conn.ConnectionString = $connStr

try {
    $conn.Open()
    Write-Host "? SQL Server 連接成功！"
    $conn.Close()
} catch {
    Write-Host "? SQL Server 連接失敗：$_"
}
```

## ?? 如果仍然失敗

### 檢查 1: 連接字符串
```json
// 應該看起來像這樣:
"PiNewsConStr": "Data Source=192.168.1.111;Initial Catalog=Pi news;User ID=sa;Password=!QAZxsw2;Connection Timeout=30;TrustServerCertificate=true;Encrypt=true"
```

### 檢查 2: 應用日誌
尋找 `[診斷]` 開頭的日誌行，查看完整的錯誤信息。

### 檢查 3: SQL Server 可達性
```powershell
ping 192.168.1.111
```

應該看到響應。如果超時，則是網絡問題。

### 檢查 4: 最後的手段 - Demo Mode
```json
// appsettings.json
"UseDemoMode": true
```

這會使用內存中的演示數據，驗證應用本身是否正常。

## ?? 常見錯誤及解決方案

| 錯誤 | 原因 | 解決方案 |
|------|------|---------|
| "TrustServerCertificate" 無效 | 舊版本 SqlClient | 更新 NuGet 包 |
| 連接超時 | SQL Server 無響應 | 檢查服務器 IP/端口 |
| SSL 錯誤 | 憑證驗證失敗 | 添加 TrustServerCertificate=true |
| 認證失敗 | 用戶名/密碼錯誤 | 驗證認證信息 |
